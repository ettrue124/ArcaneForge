# Implemented Forge playback adapters

`engine-bridge/ForgePlayback.java` subscribes to Forge's synchronous game event bus. It keeps a bounded, non-destructive journal. Each MatchDoor connection reads after its last successfully published cursor. This captures multiple events between board snapshots and avoids replaying acknowledged effects.

`protocol-host/BattlePresentation.cs` converts the following events to the installed Arena annotation contracts:

| Forge event | Arena annotation | Data supplied |
|---|---|---|
| Player/card damaged | DamageDealt | Source, target, amount, combat/direct type; markDamage=0 because the snapshot includes damage |
| Spell/known ability resolution and stack removal | ResolutionStart / ResolutionComplete | Source instance and printing/ability grpId; completion follows stack cleanup |
| Player shuffled | Shuffle | Player seat; empty OldIds/NewIds because our instance IDs remain stable |
| Card tapped/untapped | TappedUntappedPermanent | Card instance, tapped=1/0 |
| Card changed zone | ZoneTransfer | Card instance, actual source/destination zone IDs, transfer category |
| Human target selection / submitted spell or ability targets | PlayerSelectingTargets / PlayerSubmittedTargets | Acting player and source card |
| Selected stack targets | TargetSpec | Persistent source-to-target relationships, one-based index, ability ID and optional divided amounts |
| Known activated/triggered stack object | AbilityInstanceCreated | Distinct stack identity, source parent, installed ability printing |

Zone/tap snapshot fallbacks skip cards already covered by the journal. New/reconnected viewers receive the current board without historical effects. A retention gap refreshes the board without replaying an incomplete journal. Unknown or unencoded card sources are skipped rather than sent as invalid native references.

Validation:

```
dotnet build protocol-host -o protocol-host/bin/TargetAudit
python engine-bridge/test_battle.py --native
python engine-bridge/test_fetch_land.py --native
dotnet protocol-host/bin/TargetAudit/ProtocolHost.dll --self-test
dotnet protocol-host/bin/TargetAudit/ProtocolHost.dll --playback-self-test analysis/playback-check.json
```

The real battle test checks spell/combat damage, source/target/amount, paired resolution events, tap/zone events and cursor deduplication, then saves snapshot pairs for the C# adapter test. The fetch-land test checks shuffle emission. C# tests exercise ordering, duplicate suppression, missing-source filtering, protobuf roundtrips, and the installed Arena resolution/shuffle event parsers.

Normal progression now uses Arena's resolve-my-effects mode and the actual Forge stack, including abilities. Pass-after-cast survives targeting and payment. Full control and manual stops retain response windows. Forge's raw legal actions preserve a response window even when an advanced-cost display mapping is unavailable. Replies to a prior board update are accepted only while the same Forge input remains pending; superseded replies refresh the request instead of disconnecting. Foreground actions and background pushes share a gate. Arena's All Attack request maps to Forge's alpha strike selection.

The native probe drives the actual C# encoder and progression logic with real Forge snapshots. The battle test checks target-link and selecting/submitted annotations, installed targeting ability IDs, automatic progression over own spells, and deliberate target choices. The fetch test checks a distinct native ability object and paired ability resolution annotations. The installed TargetSpec parser verifies one-based wire indexes become zero-based client indexes.

Triggered ability identity now uses Forge's complete `TriggerDescription`, including the triggering condition. Bristly Bill's effect has no standalone `SpellDescription`; previously its target request had ability ID zero and its stack object was omitted. Landfall now maps to the installed 171897 ability. Target requests carry the current targeting group and actual targeting player. Stack zone ordering follows Forge's top-first stack, including mixed spells and ability instances. Automatically passed stack priority steps wait 150 ms after publication, and the background loop polls at 75 ms while the pause is pending; Full Control cancels automatic passing. This is a presentation pause, not acknowledgement of completed client animations.

Activated, targeting and stack abilities share the same conservative text mapping. HTML tags, Arena mana-symbol `o` prefixes and balanced parenthetical reminders are normalized on both sides; only one exact normalized ability match is accepted. Ba Sing Se's reminder paragraph no longer prevents its earthbend action/target/stack ability from mapping to 192869, and its green mana ability maps to 1005. Current Forge core card types override printed metadata, so an earthbent land has both Creature and Land while preserving its real power, toughness and typed +1/+1 counters. `test_tifa_earthbend.py` verifies two earthbend activations produce a 2/2 then 4/4 with two then four counters, and verifies Tifa's native 189386 landfall trigger, doubled power and end-of-turn expiry. Tifa doubles power, not counters.

Forge snapshots advertise `canUndo` only at human priority when its undo stack permits the action. Arena priority requests carry `allowUndo`, and the native `UndoReq` (RespId zero) calls the authoritative controller's undo, restoring tapped status and generated mana. Normal progression holds priority for legal non-mana plays, required choices, or explicit stops/Full Control. Reversible floating mana alone does not create a stop. Undo is not advertised during casting/payment or after reversibility is lost. `test_manual_mana.py` checks tapping, undoing, retapping and then casting from floating mana. Native client tests verify the undo flag and the actual request produced by BaseUserRequest.Undo.

Turn/phase transitions emit `NewTurnStarted` (active seat as affector) and `PhaseOrStepModified` (`phase`, `step` integer details). The installed native diff generator does not synthesize these events from TurnInfo. Its event parsers and UX translators use them to update TurnController and the phase ladder. The full native message-pipeline test checks a new opponent turn and combat/declare-attack step produce the matching events. Unchanged phases do not replay an event. Arena's built-in expanded phase ladder is a per-profile preference toggled with L; server phase events do not force that preference.

`python engine-bridge/test_landfall_stack.py` verifies real Bill/Chocobo landfall targeting identity/source, distinct simultaneous native stack objects, wire stack order, paired Forge resolution order and counters on the selected creature. Timing tests verify that automatic stack passing waits and resumes, that each new step gets its own pause, and that resetting for manual control clears the pause. Native stack rendering and final visual timing still need a match check.

Library visibility now comes from each card's actual Forge viewing permissions. The owned library's top-first order is preserved, permitted cards retain their real printing and native legal actions, and hidden cards omit identity and stats. Permissions are recalculated after draws, plays, shuffles and removal of their granting effect. Traveling Chocobo's top land/Bird actions use the same validated Forge ability route as hand actions.

Counter state uses typed persistent `Counter` annotations (`counter_type`, `count`). Changes on existing battlefield cards produce `CounterAdded`/`CounterRemoved` with the actual net transaction amount. Zero counts disappear, separate types retain separate native badges, and reconnects load current counts without replaying additions. Arena's installed counter assets choose the appearance. These changes are coalesced between snapshots, not a per-transaction counter journal. Unknown/custom Forge counter types without a matching installed Arena enum are omitted. Player counters are not covered.

Simultaneous SpellAbilityView triggers use Forge's proposed order automatically, so multiple Hydra/Chocobo triggers do not wait for an untranslated ordering dialog. Other order dialogs remain choices; a manual native trigger-order UI is not implemented. `python engine-bridge/test_library_counters.py` checks real top land/Bird plays, changing top visibility, typed Hydra counter growth and native counter change annotations. C# parser tests cover distinct types, exact deltas, removals, permission revocation and opponent hiding.

State publication now groups the board, settings and interaction in one envelope, with `pendingMessageCount` counting every follow-up. The installed GreInterface withholds its GameStateUpdate until these messages arrive, so the request belongs to the same playback update as its board. Initial/reconnected boards remain Full; subsequent boards are Diff with the prior published state ID, complete changed object records and explicit deleted object/persistent annotation IDs. Zones and players are complete replacement records. This clears spent mana, untaps, revoked library identities, removed ability objects and expired counters. Canonical boards and playback cursors are committed after the entire batch is written. Timer ticks no longer republish identical states. Cast pass intent and pacing are acknowledged after the engine action succeeds rather than when a readiness check runs.

`BattleUpdatesTests` exercises the installed GreInterface merge and complete ProcessMessage pipeline. It verifies grouped settings/request delivery produces one update with an interaction, a subsequent incremental update stays incremental, and deletions and scalar/list clearing survive the native merge. `--playback-self-test analysis/playback-check.json` compares native-merged real Forge snapshot pairs against the canonical objects, zones, players, counters, actions and playback annotations. These are headless protocol checks, not a visual animation check.

Forge snapshots now preserve Aura/Equipment attachment targets. The bridge emits Arena's persistent `Attachment` state annotation and `AttachmentCreated` when an attachment is newly assigned or moved, allowing the client to maintain its native attachment relationship and playback. `BattleAttachmentTests` runs the installed Arena message pipeline across attachment, unchanged state, reassignment, detachment, a move to the graveyard, hidden/missing targets and reconnect. The check confirms stale links are cleared and reconnects do not replay attachment events. Visual match confirmation is still needed.

This does not implement every row in the static inventory. Ability printings are mapped only when the effect text has one exact normalized match in the installed database; unmatched and ambiguous abilities remain unencoded. Fight-specific damage classification, prevention/replacement visuals and specialized card effects remain outside these adapters. Forge snapshot capture plus its event journal is not atomic on the game thread; brief concurrent changes remain possible even though Arena receives incremental updates. Temporary phase stops expire after leaving their selected phase, and the server publishes the changed settings. Specialized auto-pass and per-card yield behavior still lack complete parity. Native rendering and animation timing require an Arena match check; parser/encoder tests alone do not verify them.

Completed Forge outcomes now produce a grouped terminal board and native `IntermissionReq`, followed by a `MatchCompleted` notification carrying the same game/match result list. The installed IntermissionWorkflow waits for final playback, runs defeat VFX, then releases the scene-transition lock after its native delay. Without this request the client stayed on the battlefield at negative life. Concessions now wait for Forge's actual outcome instead of racing it with an empty result. No new gameplay requests or automatic passes are issued after completion; the terminal publication is committed once under the push gate. Life totals alone never determine the winner. Forge supplies the loss reason for life, poison, decking and concede effects. A game-over flag without a ready outcome is temporarily published as Play rather than prematurely locking the match scene. Tests exercise the installed GreInterface IntermissionRequest/GameEndEvent/loss-context pipeline for win, concede and draw, and actual MatchDoor output ordering/results/duplicate suppression against an isolated loopback fixture backend. A real Forge battle verifies lethal outcome and loser metadata. Visual end-screen validation is separate from these headless checks.

Target selection uses Forge's validTargetTypes rather than a generic card-picking prompt. Bristly Bill's landfall uses native ability 171897 and prompt 1629 ("Choose a creature"), retaining every legal creature target, including opponents' creatures. Its 171898 counter-doubling activation remains separate and does not request a target. Each target ID has exactly one Select/Unselect record; selected counts are deduplicated. Single optional creature choices use prompt 11005, and other target counts use SelectTargetsWorkflow's native count override. The installed SelectTargetsRequest constructor and protobuf roundtrip are checked in self-tests. `python engine-bridge/test_bill_abilities.py` verifies the actual Forge landfall request, separate activation/stack identity, counter doubling and an AI victory after human concede. Registered participants determine permanent wire seats, including after a defeated player leaves Forge's active player list. These checks do not visually verify Arena's scene/menu rendering.

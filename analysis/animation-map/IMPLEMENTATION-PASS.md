## Added

- Regeneration: actual GameEventCardRegenerated, rather than inferring regeneration from a tap.
- Control changes: changed controller seat, suppressed on unchanged boards and reconnect.
- Coin flips: every actual random/forced coin result, including repeated equal results; no rerolling or altered decisions.
- Dice: actual natural and modified results, die sides, and ignored rolls, captured after Forge decides the outcome.
- Creature type choices: newly selected subtypes produce native ChoiceResult playback for the controlling player, with no repeat on unchanged boards.
- Chosen colors and nonnegative numbers: Forge's stored choices populate native LinkInfo state and ChoiceResult playback. Color sets are normalized to prevent replay from reordered values; zero is a valid chosen number. Native full/diff checks cover multi-color state and both domains. - Regeneration shields: persistent shield counts are sent before damage; native checks cover unchanged updates and expiration without accumulation.
- Current creature subtypes and supertypes now follow Forge rather than the original printing, enabling native type-change playback.

- Copies: resolve the copied printing through Forge's actual clone origin, send copied-object state, retain original identity and avoid a false reverse-side link. Copy exceptions with changed names are left unresolved rather than selecting unrelated artwork.
- Multistep effect playback: actual scry, surveil, explore, proliferate and connive decisions emit start/finish boundaries with the native ability category and affected player. Replaced/declined effects do not start playback. Surveil/explore/proliferate/connive finishes use finally blocks; scry finishes after the chosen cards move. This observes decisions without adding new ones.

The markers don't apply numeric deltas, don't repeat stat animations and expire with the buff. ## Remaining evidence boundaries

These checks validate rules events and message contracts, not the visible Unity rendering. Concrete asset payloads and all cosmetic clip variants are not enumerated. The complete 120-class inventory includes UI scheduling, tutorial handlers, base classes and state-driven visuals; it is not 120 distinct animations.

Other contracts still require dedicated rules data: pending counter transfers, layered/perpetual effects, domain-specific choice results, designations beyond the implemented five, illegal attachment causes and other multistep effect categories. These are listed in the trigger map without claiming that a missing explicit annotation proves a missing visual. Snapshot-driven changes can already produce some of those visuals. No generic placeholder effects were added.

The installed SharedClientCore AnnotationEventsPreProcessor reconstructs LayeredEffectCreated without its Type collection, so AnnotationEventProcessor cannot select its event parser. A native pipeline check confirmed that a synthetic layered color event produces no Colors event; current colors themselves update. No ineffective synthetic annotation is shipped. Resolving this visual limitation requires observing the official client's actual traffic/visual behavior or a separately authorized client change. Full animation parity is not established.
